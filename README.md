# SOS Escola

Aplicativo de capacitação em primeiros socorros na escola, conforme a Lei Lucas.

## Firebase e Vercel

O deploy do Vercel usa `vercel.json`: instala as dependências, executa `npm run build` e publica `html/` com Node.js 22 ou superior. O build gera o bundle do Firebase usado pelo site. O navegador cria contas e grava os perfis no Realtime Database; as rotas em `api/` classificam instrutores, reconciliam permissões e fornecem as listas autorizadas usando o Firebase Admin SDK. Credenciais administrativas nunca devem ser incluídas nos arquivos do site.

### Configuração do cadastro

1. No Firebase Console, habilite **Authentication → E-mail/senha** e adicione o domínio do site em **Authentication → Configurações → Domínios autorizados**.
2. No Vercel, configure `FIREBASE_SERVICE_ACCOUNT` com o JSON de uma conta de serviço dedicada e crie as variáveis secretas `HEALTH_INSTRUCTOR_SIGNUP_CODE` e `RESCUE_INSTRUCTOR_SIGNUP_CODE` para os convites das respectivas áreas. Os códigos são comparados apenas no servidor e não devem ser incluídos no código-fonte, HTML ou JavaScript do cliente.
3. Dê à conta de serviço as permissões Firebase Authentication Admin e Realtime Database necessárias para classificar instrutores e administrar contas. Salve os valores como variáveis privadas do Vercel; nunca os envie pelo chat, publique no repositório ou coloque no HTML/JavaScript.
4. Publique as regras do Realtime Database com `npx --yes firebase-tools@latest deploy --only database --project sos-escola-a6ccb`. O projeto publica `database.rules.json`; as regras permitem que cada usuário grave apenas o próprio perfil, impedem que ele altere seu papel e limitam a foto a uma string JPEG curta.
5. Faça um novo deploy do Vercel depois de configurar as variáveis.

O cadastro cria a conta com Firebase Authentication e grava o perfil inicial no Realtime Database. Para instrutores, o campo Código de Acesso é validado no servidor antes da criação da conta e novamente antes de atribuir permissões; tentativas inválidas são limitadas, e os códigos nunca são incluídos no JavaScript público. O código de saúde ou segurança/resgate configurado nos segredos do Vercel define a classificação. O perfil guarda `tipo` como `profissional-saude` ou `profissional-seguranca-resgate`, e `profissaoInstrutor` como `saude` ou `resgate`, respectivamente. Sem código de instrutor, a conta é de equipe escolar e exige a função na unidade. Contas antigas sem classificação são encaminhadas para uma tela de migração após o login. Cada pessoa cria uma senha Firebase própria (mínimo de 6 caracteres); o código de convite não é a senha da conta. O papel de instrutor dá acesso à área de avaliação do app, não privilégios administrativos no projeto Firebase. Um código curto e compartilhado continua sujeito a tentativa de adivinhação; prefira um segredo longo e aleatório.

O cadastro guarda nome, e-mail e função escolar no perfil do Realtime Database. A aba pessoal permite enviar uma foto JPEG, PNG ou WebP de até 5 MB; ela é redimensionada e convertida no aparelho para JPEG Base64 com menos de 100 KB, então salva somente na propriedade `foto` do próprio perfil. Não é necessário configurar Firebase Storage. Instrutores de saúde e de segurança/resgate usam checklists próprios; cada avaliação prática guarda nota individual de 0 a 10 e observação opcional. A lista de participantes contém somente pessoas instruídas, não contas de instrutor.

Se o domínio for recusado durante o cadastro, adicione o domínio do site em **Firebase Authentication → Configurações → Domínios autorizados**. Se o Realtime Database retornar `PERMISSION_DENIED`, publique `database.rules.json` e confirme que as regras permitem a gravação do perfil pelo próprio usuário.

Na aba Perfil, pessoas instruídas podem avaliar o instrutor e a capacitação (notas de 1 a 5 e comentário); o feedback é identificado e só o instrutor avaliado pode consultá-lo. Cada usuário pode pedir a exclusão da própria conta. A tela pede confirmação e, após confirmar, o servidor remove o acesso, perfil (incluindo a foto Base64) e registros associados; a exclusão não pode ser desfeita. As métricas mostram cadastros, resultados de questionários, checklists e notas práticas. A lista de participantes valida cada perfil contra o Firebase Authentication, portanto contas removidas não continuam visíveis mesmo que o nó de perfil ainda exista no Realtime Database. O endereço do Realtime Database fica no código cliente e não é uma credencial; a proteção dos dados depende da autenticação e das regras. Não use regras públicas de leitura ou escrita.
